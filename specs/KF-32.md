# KF-32 — Structured data-access contracts

**Priority:** P2 · **Depends on:** KF-28, KF-31 · **Enables:** KF-33, 34

## Goal / baseline

`writeDataAccess` picks a generic authoritative sentence, writes a fixed `events/data-access.md` and abstains if any DataAccess exists. Represent how agents obtain current data, without caching rows or granting new access. Multiple domains/providers and access methods must coexist.

## Format / interfaces

Keep OKF Markdown concept and `item_type=data-access` (migration 007). Define versioned `data_access` metadata in OKF frontmatter (or associated validated YAML companion if OKF rejects extension; document exact mapping and preserve conformance). Schema `schemas/data-access.schema.json`. Normative required fields: `schema_version: 1`, `id` stable slug, `domain`, `owner`, `source_ref` allowed registered connection ID + logical resource ID (not credential/URL), `provider` enum (`http`, `grpc`, `postgres`, `bigquery`, `kafka`, `pubsub`, `temporal`, `observability`, `other`), `access` object (`tool` registered logical name, `mode: read-only`, `auth_ref` logical policy reference, `required_permissions[]`, `parameter_schema` bounded JSON Schema subset), `freshness` (`query-at-runtime`, optional max_age_seconds), `validation` (`contract_ref`, revision, expected schema/result checks), `scope`, `classification`, `sources[]` exact authoritative refs, `last_reviewed`, `review_due`, `status`. Optional limitations and example placeholders; no live URLs containing credentials, SQL with customer literals or raw rows. Tool name is advisory; agent runtime must independently possess permission. `DataAccessValidator.Validate(contract, sourceRegistry, policy)` pure metadata validation; no runtime query execution. `knowledge.search` type filter includes `data-access`; `knowledge.get` returns Markdown + typed safe metadata or separate `data_access` structured field, revision and provenance. Public contracts only if source shareable and approved.

Example:
```yaml
type: DataAccess
title: Read movement lifecycle events
status: stable
data_access:
  schema_version: 1
  id: movement-lifecycle-events
  domain: payments
  owner: payments-platform
  provider: kafka
  source_ref: {connection_id: banking-contracts, resource_id: movement.lifecycle.v2}
  access:
    tool: kafka.consume
    mode: read-only
    auth_ref: payments-read-policy
    required_permissions: [topic-read]
    parameter_schema: {type: object, properties: {event_id: {type: string}}, required: [event_id], additionalProperties: false}
  freshness: {strategy: query-at-runtime}
  validation: {contract_ref: movement-lifecycle-avro, revision: fixture-revision, checks: [schema-match]}
  scope: workspace
  classification: workspace-shareable
  sources: [fixture-source-ref]
  last_reviewed: 2026-11-24
  review_due: 2027-02-24
```
Example values are synthetic; real validation resolves source and contract IDs/digests. No implicit access to Kafka.

## Implementation sequence

1. Add typed contract/parser, JSON schema and validation (ID unique within workspace bundle; required fields, enums, references, read-only, size/depth, safe parameter types, no executable templates). Provider-specific requirements: topic/schema for Kafka/PubSub, operation/method for HTTP/gRPC, logical view/table for SQL, workflow/task query for Temporal, logical signal/query ID for observability. Resource identifiers mapped to registered contract metadata; validate no wildcard/destructive access. `other` only explicit operator-defined read-only tool schema. Unknown provider/permission -> reject or draft. No unbounded free-form query generation.
2. Refactor curator data-access synthesis to locate by stable domain/resource identity and exact gap, use evidence spans from KF-28 and sources from KF-31; create or update appropriate unique path (e.g. `data-access/<domain>/<id>.md`), not fixed file. Multiple contracts allowed. Map source evidence to every normative field; if missing tool/auth/schema info abstain rather than invent. Existing legacy DataAccess pages migrate via reviewed Git PR or treated as unstructured advisory concept/draft; never silently make approved new metadata. Fixture migration must preserve retrieval compatibility where safe.
3. Integrate validation in OKF load/candidate gate and search/get. Index safe metadata and field-specific terms; add data-access filter description to MCP schemas. No source connector execution from knowledge retrieval. Include examples for Kafka, gRPC and Temporal with synthetic contract refs, document extension points for PubSub/BigQuery etc (provider metadata support, not implemented live connector). Handle revoked source via KF-31 filters. `kfactory validate` reports missing required field with safe path/code.

## Security / failure handling

Contracts describe access, not grant it; never call external resource merely from retrieval. No writes, raw data, tokens, secret refs that disclose credential values, PII, arbitrary URL/shell, embedded scripts, destructive SQL or real customer payload. Validate scope and permission independently at publication and read. Unverified provider metadata or stale/revoked contract -> nonpublishable/withdrawn; explicit warning for stale review if policy permits. No guessing tool availability.

## Acceptance criteria / tests
- **32-A:** Two different valid contracts coexist and retrieve independently by domain/resource/type; no fixed-path collision.
- **32-B:** Existing contract update changes only intended resource; duplicate ID, unknown field/provider, invalid tool, write mode, credential or missing source rejected.
- **32-C:** Model proposal with invented auth/tool/schema fails evidence gate; legacy page is not promoted as validated structured contract.
- **32-D:** Search/get returns active revision, safe typed metadata and source provenance; revoked/other-workspace contract inaccessible.
- **32-E:** Tests assert retrieval makes zero network/tool calls and no rows or secrets persisted; fixtures cover Kafka/gRPC/Temporal and schema-negative cases.
- **32-F:** Full candidate evaluation and human PR approval required; compatibility docs and CLI validate output updated.

Add `internal/knowledge/dataaccess`, schema fixtures/tests, curator and index/MCP tests; update `examples/banking` and docs. Run shared gates. **Done:** validated reusable access instructions with no execution/privilege grant.

## Non-goals

Live Kafka/PubSub/BigQuery query connectors, data replication, credentials broker, agent tool execution or arbitrary SQL generation.

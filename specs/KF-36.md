# KF-36 — Learning effectiveness metrics

**Priority:** P2 · **Depends on:** KF-27, KF-35

## Goal

Measure the factory's effectiveness rather than count documents or PRs. Combine scoped run outcomes, candidate/gap lifecycle and comparative execution receipts. Clearly distinguish observational production metrics from controlled replay results. No ungrounded claims that knowledge caused a production improvement.

## Metric contract

Expose `GET /v1/metrics/learning?from=<UTC>&to=<UTC>&task_kind=...` for curator/reviewer; range max 90d default 30d, optional explicit release filter, workspace from principal. `kfactory metrics learning --from ... --to ... --format json|markdown`. Output schema version, workspace, range `[from,to)`, `as_of`, filters, dataset/release/config versions, data completeness, metric rows with value/unit/numerator/denominator/sample_size/status (`ok|insufficient-data|unavailable`), source definitions and caveats. Null for zero denominator, never substitute zero. Counts distinct canonical IDs/runs; no duplicates/retries. Source cohorts use `run.completed` with independent result when required, received-time cutoff and event-time window explicitly documented. Keep UTC and deterministic recomputation.

| Metric ID | Formula / grain |
|---|---|
| task_success_rate | independently verified successful completed runs / completed runs with known independent outcome; exclude unknown/cancelled/invalid, report excluded count and coverage |
| replay_task_success | passing eligible paired trials / valid paired trials, per arm and dataset/config digest; report invalid required trials separately |
| replay_paired_delta | mean(candidate_pass - baseline_pass) over valid paired case-trial pairs, percentage points; include improved/regressed/tied counts |
| recurring_knowledge_failure_rate | distinct completed failed runs linked to a recurring knowledge hypothesis / known completed runs in same cohort; label suspected not causal |
| human_correction_rate | distinct completed runs with classified human correction / eligible completed runs; also count corrections per 100 runs separately if needed |
| retrieval_no_hit_rate | authorised retrieval events with zero hits / all observed authorised retrieval events; exclude missing telemetry, report coverage |
| proposal_acceptance_rate | merged proposals / (merged + rejected/closed-unmerged proposals) with terminal decision in window; pending excluded and shown |
| gap_resolution_latency | p50/p95 time from canonical gap creation to first published receipt, and separately first verified receipt; only completed gaps, report open backlog and age to avoid survivor bias |
| verified_gap_rate | gaps with valid targeted proof / distinct published gaps in cohort, as of report time; show invalidated proof separately |
| knowledge_recurrence_rate | verified gaps with linked recurrence within fixed follow-up (default 30d) / verified gaps whose full follow-up window elapsed; censor recent gaps |
| critical_regressions | count critical regressions in candidate eval receipts and separately promoted release critical regressions; target promoted zero |
| unsafe_exposure | observed unauthorised/revoked/staged exposures from audited tests/incidents; zero observed is not proof of zero risk |
| curator_cost_per_accepted | known model token/cost totals for linked attempts / merged proposals; report missing usage and currency/tariff version, cost null if unknown |

## Implementation sequence

1. Define typed metric registry with stable ID, numerator/denominator SQL, cohort/time semantics, source tables, owner and version. Use existing events/receipts, not infer from mutable state. For first version aggregate on demand bounded range with indexes `(workspace_id, event_time/status)`; only materialise if measured need, preserve reproducibility. Keep task kind filters exact and unknown bucket; release attribution based on recorded run revision, not current active pointer. Use transaction-consistent `as_of`; late events may revise previous reports, disclose. Redaction and retention mean older coverage may be incomplete. Add explicit data completeness counters (known outcomes, runs with revision, retrieval telemetry, independent proof).
2. Build `internal/metrics/learning` query service; RLS scope every query, no dynamic untrusted SQL identifiers, limits and timeout. Count distinct canonical gap/attempt/proposal and dedup events. For replay report only same dataset/config paired comparisons; do not average different models as causal result. Separate observational time trend by release/task kind from controlled replay. For before/after cohorts require comparable task kind/model/tools and window; if not comparable, report descriptive only and caveat. No automatic target achievement from tiny sample; display sample sizes, minimum default 20 runs for trend interpretation (still show counts). No statistical inference for synthetic data.
3. Extend OTel/Prometheus-compatible existing instrumentation with low-cardinality counters/histograms (event kind, decision, outcome, detector reason, mode); do not expose workspace/customer/user IDs as public labels. API metrics protected; health no sensitive details. Optional internal metrics scrape endpoint must be network-restricted/authenticated. Distinguish operational counters reset on restart from durable reports. Document retention, measurement definitions and how to interpret sample-size/unknown values.
4. Add `examples/banking/tests/metrics-fixture.json` with hand-computable event, gap, PR, rollback and replay receipts; include duplicates, unknown outcomes, censored gap, invalid trial, rejected proposal, revoked proof, mixed releases and cross-tenant row. Assert exact numerator/denominator/latency. Add report sample generated by test or CLI (label synthetic), target values only as goals, not current measurements. Suggested initial guardrails: no promoted critical regressions, no unapproved exposures, 100% accepted changes with evidence receipt; task success/recurrence improvement baseline-dependent, not universal SLA.

## Security / failure handling

No raw traces, prompts, user identities or source text in metric response/logs. Authorise curator/reviewer; agent cannot infer other agent activity from aggregate API unless explicitly allowed later. Cross-workspace query forbidden, small cohorts may be sensitive; expose to trusted roles only and suppress optional breakdown below configurable threshold. Unknown denominators -> null with reason. Unavailable store returns 503, no fabricated zeros. Do not retain metric material beyond policy; audit access and exports as appropriate.

## Acceptance criteria / tests
- **36-A:** Hand-calculated fixture matches every metric's exact numerator/denominator, including duplicates, pending, unknown and invalid trials.
- **36-B:** Window boundaries, late arrivals, timezones, release/task filters and zero denominator handled deterministically; censored recurrence not counted as nonrecurrence.
- **36-C:** Rollback invalidates current proof without erasing historical verification; metrics show both.
- **36-D:** Mixed model/config cohorts not presented as causal improvement; paired delta only matching pairs; missing cost null.
- **36-E:** Workspace/role isolation, no raw IDs/text in telemetry labels, retention/completeness caveats visible.
- **36-F:** JSON and Markdown reports agree, query budget respected, unavailable DB not success; integration with demo reports actual measured fixture outcomes.

Add `internal/metrics/learning` and API/CLI tests with real Postgres RLS. Run shared gates. **Done:** reproducible, inspectable learning metrics with definitions, coverage and limits, not vanity counts.

## Non-goals

BI platform, dashboard frontend, billing system, automated optimisation based solely on metrics, production causal attribution.

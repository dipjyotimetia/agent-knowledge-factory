# KF-04 Knowledge index

## Goal

Answer a workspace-scoped full-text query from the published Git SHA only. Draft, deprecated, superseded, and other workspaces' documents are not results. Rebuilding the index from the knowledge directory is the recovery path.

## Inputs / outputs

- Input: an OKF + skills directory, a SHA, a workspace id, and a query.
- Output: ranked hits with URI, revision, snippet, trust tier, stale warning, and source URIs. `GET /v1/knowledge` returns the full published item.

## Non-goals

- MCP transport (KF-05).
- Embeddings or pgvector.
- Treating an unmerged curator edit as published.

## Interfaces

- `index.Service.Reindex`
- `index.Service.SyncDelivery` — a repeated webhook delivery id does not publish again
- `index.Service.Search` and `Get`
- `GET /v1/search`, `GET /v1/knowledge` (bearer token; `workspace_id` must match the token)
- `kfactory index` and `kfactory search`

Search filters `approved`, `status = stable`, empty `superseded_by`, and `git_sha = workspaces.published_sha` before ranking. Ranking is `ts_rank` plus title trigram. The query `dedupe` also searches `deduplicate`.

## Failure modes

- Non-conformant bundle or invalid skill: reindex refuses and leaves the published SHA unchanged (the write is one transaction).
- Empty query: `ErrInvalidQuery`.
- Unknown URI or a SHA that is not the requested revision: not found.
- Duplicate webhook delivery: no second publish.

## Tests

The banking fixture is published. Search for the dedupe guide returns the stale lifecycle concept with provenance and a stale warning. `DRAFT_ONLY_MARKER` and another workspace's token are absent. After a new SHA that deletes the guide, default search and get no longer return it. A repeated delivery id is a no-op.

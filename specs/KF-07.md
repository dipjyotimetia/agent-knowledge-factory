# KF-07 Curator

## Goal

Produce a minimal knowledge edit whose new tokens are present in pinned contract evidence, or escalate. The deterministic curator is the mocked curator used by the banking loop. A human can submit the same shape of edit and it passes the same gate.

## Inputs / outputs

- Input: gap category, current knowledge files, and evidence snapshots (location, revision, digest, classification, untrusted content).
- Output: a proposal with decision `update`, `no-change`, `escalate`, or `insufficient-evidence`, plus edits and a claim-to-evidence map when the decision is `update`.

## Non-goals

- Opening the pull request (KF-08).
- Calling a live model. The OpenAI-compatible adapter is added after this deterministic loop exists, in KF-09, and the demo does not require it.
- Treating model prose or wiki text as evidence.

## Interfaces

- `curator.Propose` with `BankingDedupeRule`
- `curator.Manual`
- `curator.Validate`
- `curator.Untrusted` wraps source text before any later model prompt

The rule reads `deduplicate by ` + a field from contract evidence and checks that field exists as `"name"` in the Avro schema. It replaces that field only where a knowledge file states a different one.

## Failure modes

- Two contract captures disagree: `escalate`, no edits.
- Schema does not contain the field: `escalate`.
- Only secondary evidence: `insufficient-evidence`.
- Category `execution-failure`: `no-change`.
- Manual edit introduces a token that is not in cited contract or policy evidence: validation error.
- A secondary document that says "set the key to password" does not change the edit.

## Tests

The recorded banking README and schema produce two edits, both to `` `eventId` ``. Conflict, manual rejection, execution failure, and the injection fixture are covered.

## Definition of done

`go test ./internal/curator` passes. No model API key is read.

# KF-16 Measured improvement

## Goal

`verified` means the gap's targeted case got better, and previously passing critical cases did not get worse.

## Inputs / outputs

- `TargetedIDs` selects `expects_change` cases whose answer appears in the gap summary, observed text, or expected text.
- `ProvesImprovement` is true only when at least one of those cases failed before and passes after, and none of them stay failed.
- `commitCandidate` also runs `RunDecisions`. A critical decision regression blocks promotion.
- `Publish` moves the gap to `verified` only when `ProvesImprovement` is true. Otherwise the gap can stay `published`.

## Non-goals

- A live agent success rate. The gate scores the static case file.

## Definition of done

`go test ./internal/evaluations ./internal/demo` passes. The banking dedupe case moves from `movementId` to `eventId` and the gap is `verified`. A proposal that breaks a previously passing critical case is not promoted.

# KF-08 PR workflow

## Goal

Open a reviewable pull request for a grounded proposal and publish the knowledge index only when the default branch head equals the claimed merge commit. The curator client has no merge operation.

## Inputs / outputs

- Input: a gap id, pinned evidence, and a publisher.
- Output: a pull request URL while the gap is `awaiting-review`. After a human merge, the gap is `published` and search returns the new revision.

## Non-goals

- Letting the curator merge.
- Calling a live GitHub repository from tests. `publish.Memory` is the forge. `publish.GitHub` is covered with httptest and refuses `/merge`.

## Interfaces

- `publish.Publisher` with `CreatePullRequest` and `DefaultHead`
- `publish.Memory.HumanMerge`, which is not on the interface
- `workflows.Steps.Prepare`, `Open`, `Publish`
- `workflows.TriageGapWorkflow`, which waits on the `review` signal and calls `GetVersion` for the wait

A claimed merge SHA that is not `DefaultHead` returns `ErrNotMerged` and does not reindex.

## Failure modes

- Decision other than `update`: gap becomes `insufficient-evidence`, no pull request.
- Pull request opened: published search is unchanged.
- Forged merge signal: publish fails.
- Human merge: reindex of the merged tree, gap `published`.

## Tests

The banking dedupe guide still says `movementId` after the pull request is opened and after a forged SHA. It says `eventId` only after `HumanMerge` and a matching publish. The Temporal test completes a non-update without publishing, and a second test publishes only once the review signal arrives.

## Definition of done

`make test` passes, including the Postgres loop and the Temporal test suite. The worker can register the workflow when `TEMPORAL_ADDRESS` is set.

# KF-17 Suggested edits and feedback

## Goal

The curator applies an agent's suggested correction when pinned evidence supports it, and it reads observations people already filed.

## Inputs / outputs

- A gap report may include `suggested_edit` with `path`, `old`, and `new`. The schema is `schemas/gap-report.schema.json`.
- `applySuggested` accepts that edit only when the new text, or its backtick token, appears in contract or policy evidence.
- `Prepare` loads unread feedback and passes `observed` and `expected` on the curator request.
- A proposal that is persisted calls `ConsumeFeedback`, so the same observation is not applied twice.

## Non-goals

- Treating feedback or the suggestion as evidence. Evidence is still the pinned source.

## Definition of done

`go test ./internal/curator ./internal/gaps` passes. A suggestion whose token is absent from the evidence produces no edit. A second prepare does not see feedback that was consumed.

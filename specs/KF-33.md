# KF-33 — Knowledge lifecycle, authority and conflict resolution

**Priority:** P2 · **Depends on:** KF-29, KF-31, KF-32 · **Enables:** KF-34

## Goal / baseline

Existing OKF status/freshness and two regex conflict patterns cannot distinguish entities, time, scope or authoritative source precedence. Define lifecycle and claim authority with explainable resolution; prevent stale/revoked guidance and contradictions from silently becoming stable knowledge.

## Contract

Keep existing OKF `status` values and map to serving lifecycle: `draft` private; `stable` eligible only in active release and current policy; `deprecated/superseded` not default served; `withdrawn` operational deny overlay (not necessarily new OKF status). Metadata: stable URI/id, domain/entity, owner, `scope` (workspace or narrower nonshareable), source links with revision/digest/classification, `valid_from`, `valid_until` optional, `last_reviewed`, `review_due`, `supersedes[]`, `policy_version`. `KnowledgeClaim{subject,predicate,normalized_value,scope,valid_interval,source_span_ids,authority_rank,knowledge_uri,release_id}`; claim identity includes entity/domain/scope/predicate, not regex token alone. Add `knowledge_claims`, `claim_conflicts`, `knowledge_lifecycle_events`, `knowledge_withdrawals` (workspace+URI+reason/release/source, active flag), `review_tasks`. Server-controlled authority policy: scope-specific authoritative policy/contract (explicit configured precedence by predicate/domain), owner-attested durable doc only if registered authoritative source, secondary docs/feedback/experience as leads. Same-authority conflict -> unresolved; no universal "newest wins" or policy-over-contract when predicates differ. Different valid scopes/periods not contradiction unless overlap. Unknown scope/time = conservative escalate.

## Implementation sequence

1. Extend OKF metadata parsing/validation without breaking v0.3 compatibility; use optional namespaced fields or documented companion metadata. Reject malformed validity intervals, missing authoritative source for new claims, dangling/cyclic supersedes refs, duplicate stable URI, owner missing for new publishable items. Existing fixtures migrate via reviewed PR; legacy metadata marked incomplete, not granted new authority. Define configurable authority rules (domain/predicate/source IDs, precedence integer, classification and shareability). Validate config and version/digest; no model-assigned rank.
2. Build deterministic claim extraction for schema/contract and configured patterns (entity-aware); bounded optional model proposes claim tuples with exact spans and uncertainty, validators require evidence, no automatic truth. Group overlapping scope/interval/subject/predicate; compare typed canonical values (case/unit normalization only where defined). Distinguish conflict, valid version change, scoped exception, duplicate. Persist conflict with stable signature including claim IDs/snapshot digests, open/acknowledged/resolved status; one gap per distinct unresolved conflict using KF-27 canonical path. Repeated scan idempotent. If authoritative precedence clear, propose reviewed correction; else escalate owner, no automatic rewrite. Negative tests same status across unrelated services and different effective dates.
3. Lifecycle scheduler reads current release and source access; create review tasks before due date (default 14d lead); expired valid_until or revoked source -> deny overlay immediately; stale review_due -> warning for ordinary low-risk guidance, deny for configured critical/policy/data-access classes; no silent permanent exceptions. Config policy makes stale handling explicit; default deny critical. `last_reviewed` only changes through verified human review, not indexing timestamp. Superseded status in Git, no auto-edit. Withdrawal overlay checks in all public reads/search count before ranking, candidate validation, rollback; generation increment fences pending receipts on trust change. Re-enable only after reviewed remediation release and policy checks, never by clearing an arbitrary flag. Retain reason codes, minimal metadata, no raw source content.
4. Operator/reviewer metadata-only commands/list `kfactory knowledge lifecycle`, `... conflicts`, `... review-due`, `... withdraw --uri --reason` (operator authority). Review action signals curator; never merges. Audit transitions and policy version, low-cardinality metrics conflicts/open/review overdue/withdrawn. Document authority resolution table and examples; integrate KF-31 revocation and KF-25 quarantine, no duplicate logic.

## Security / failures

Source authority immutable per snapshot plus current policy permission; permission loss overrides historical approval. Do not elevate a human suggestion into policy. Narrow scope never leaks to workspace-wide retrieval; unknown scope denied. Expiry uses trusted server clock (injectable). On missing policy, required authority or source validation fail closed for affected items; no arbitrary precedence tie breaker. Public read and index filters consistent including explicit SHA. No secret values in claim text/audit; store minimal evidence refs.

## Acceptance criteria / tests
- **33-A:** Two identical predicates in different entities/scopes/time windows don't conflict; overlapping authoritative different values create one conflict and gap.
- **33-B:** Explicit authoritative precedence produces correction candidate; equal/unknown authority escalates; secondary source never overrides contract.
- **33-C:** Review due vs valid_until handled by documented policy, time controlled; last_reviewed not reset by reindex; stale critical/data access denied.
- **33-D:** Revocation/withdrawal prevents search/get/rollback and pending promotion; remediation only after reviewed release; audit history retained.
- **33-E:** Cycle/dangling supersedes, invalid interval, duplicate URI and missing owner/source fail validation for new items; legacy migration safe.
- **33-F:** Concurrent scan/refresh idempotent; cross-workspace, secret/injection and missing policy cases fail closed; unaffected items available.

Add claim/lifecycle package, extend OKF tests, `curator/scan_test.go`, publication/index and PostgreSQL integration tests. Run shared gates. **Done:** scoped, explainable authority and lifecycle, no unsafe stale guidance exposure.

## Non-goals

Graph database, universal automated entailment, full per-document user ACL, automated Git deletion or approval.

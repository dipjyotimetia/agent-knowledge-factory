# KF-02 Format

## Goal

Read Open Knowledge Format v0.3 bundles and Agent Skills the way their specifications define them, and reject documents that are not conformant. The banking demo corpus is a valid bundle with one intentionally stale dedupe rule.

## Inputs / outputs

- Input: a directory tree.
- Output: concepts or skills, plus error and warning diagnostics. `kfactory validate` exits non-zero when any error is present.

## Non-goals

- Indexing into Postgres (KF-04).
- Executing attesters, executors, or skill scripts.
- Rewriting documents. Validation is read-only.

## Interfaces

- `okf.Load`
- `skills.Load` and `skills.LoadTree`
- `kfactory validate [path]`

Rules implemented from OKF v0.3 (spec dated in the upstream SPEC.md, read 2026-11-23):

- `index.md` and `log.md` are not concepts. A subdirectory index and any log must not have frontmatter.
- A Markdown file with no `type` is not a concept. Unknown keys are kept. Unknown `type` values are accepted.
- Duplicate keys and custom YAML tags are rejected. Unclosed frontmatter is rejected.
- Trust tier uses only current `verified` events. Only a `human:` actor yields human-reviewed.
- A `stale_after` value that does not parse is not fresh. Broken links are not errors.
- An Attested Computation without `runtime` and `attester` is not attestable. Nothing in the bundle is executed.
- Symlinks that resolve outside the bundle are not read.

Rules implemented from the Agent Skills specification (agentskills.io, read 2026-11-23):

- `name` is 1–64 characters, lowercase letters, digits, and single hyphens, and matches the directory.
- `description` is 1–1024 characters. `compatibility`, when present, is 1–500. `metadata` is a string map.
- Paths in the body are relative to the skill root.
- Files under `scripts/` are hashed and returned as data. The loader never executes them.

## Failure modes

- Malformed YAML, duplicate keys, escaping symlinks, escaping skill paths, and illegal skill names are errors.
- Missing optional OKF families, broken links, and unknown status values do not make the bundle non-conformant. Unknown status is excluded from "current".

## Tests

- `examples/banking/fixture-knowledge` is conformant, human-reviewed, stale, and still says `movementId`.
- Malformed bundles and illegal skills fail.
- A script that would `touch` a marker does not create that marker.

## Definition of done

`kfactory validate examples/banking/fixture-knowledge` succeeds. The tests above pass under `make test`.

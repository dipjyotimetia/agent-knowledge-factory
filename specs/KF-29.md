# KF-29 — Human feedback classification and learning

**Priority:** P1 · **Depends on:** KF-26, KF-28 · **Supersedes:** KF-17 workspace-wide consumption

## Goal / baseline

`UnreadFeedback` reads all unread workspace observations and `ConsumeFeedback` marks all consumed after any proposal. `HumanLines` detects only line additions, losing semantics and attribution. Preserve feedback scope, authority, correction type and lifecycle; avoid learning transient preferences or unrelated instructions globally.

## Contract

Extend feedback model with immutable `feedback_id,actor_id,actor_role,channel,run_id,knowledge_uri,observed_release,source_event_id,received_at`, bounded sanitised observation; classification record `kind` (`domain-correction|procedure-correction|data-access-correction|user-preference|task-context|temporary-exception|review-comment|unknown`), `scope` (`task|actor|team|workspace`), `scope_id`, `valid_from`, optional `valid_until`, `authority` (`unverified|reviewer-attested|source-backed`), confidence reason (not calibrated probability), `status` (`new|classified|linked|dismissed|expired`), classifier version. Team scope is metadata only until ACLs exist: team-specific content must not enter workspace-wide index without explicit workspace-shareable approval. `proposal_feedback_links` unique proposal+feedback; `feedback_classifications` append-only; no global consumed marker for new processing. Existing `knowledge.submit_feedback` fields remain accepted; optional correction type/scope/expiry are hints not trusted. Role assigned from principal; agents cannot impersonate human/reviewer. Reviewer CLI/API records classification/attestation with reason, not Git merge authority.

## Implementation sequence

1. Migrate existing feedback rows to unverified/unknown; preserve consumed_at as legacy metadata, not proof of use. Derive actor/run ownership where verifiable, otherwise unknown. Validate URI/release/run within workspace, only allow observations of published release or previously recorded authorised run; no staged refs. Bound text 4 KiB and refs; sanitise before DB. Provide stable idempotency event ID for new clients; compatibility legacy submissions assigned server ID and documented no dedup without client ID.
2. Implement deterministic classification defaults (explicit task-only/expiry hints cannot become workspace knowledge); optional bounded classifier via KF-28 budget receives sanitised text/context, outputs schema enum and reason, not authority. Uncertain -> unknown, manual review. Source-backed status derived only from evidence validator. Reviewer attestation alone is a lead unless configured authoritative policy source is updated; no blanket upgrade by role. Personal/task preference stays local experience, never published workspace knowledge. Temporary exception requires expiry and policy owner; do not turn into permanent rule. Propose knowledge update only for scoped durable correction with evidence.
3. Replace global feedback queries with `ListRelevantFeedback(ctx, attemptID, scope, knowledgeRefs, runIDs, release)`; stable sorted, max 20, exact refs or explicit candidate links, skip expired/dismissed. Persist links to exact proposal/attempt and classification version transactionally with proposal; no lost unrelated feedback. A rejected proposal retains feedback available for controlled new attempt; prevent same feedback generating infinite proposals without new evidence. Concurrency: row locks/unique links and no cross-attempt mutation. Support multiple legitimate proposals when distinct affected knowledge; record disposition per link.
4. Replace `HumanLines` heuristic with semantic diff capture of exact approved PR head versus proposed full tree and final merged tree; include additions/deletions/replacements and path/digest. Attribute to verified forge review/commit metadata if available; if unknown, label unknown. Do not assume every merge edit is human or a new rule. Store bounded sanitised correction event linked to PR, attempt, revision, path; idempotent per PR+diff digest. Classify before opening follow-up gap; avoid self-generated PR loop. No source/body in audit event. Provide curator/reviewer list of classified feedback with filters and disposition; user-facing agent reads only own acknowledgement.

## Security / failures

No cross-workspace/actor preference leak. No feedback can change knowledge directly or override authoritative contracts. Unknown authority/expiry stays nonpublishable. Human correction may contain personal/customer data or injection; same redaction and untrusted tool gates apply. Review action authenticated; never trust submitted role/identity. Failure to classify leaves queued, not discarded or consumed. Do not treat Git commit author alone as proof of policy authority.

## Acceptance criteria / tests

- **29-A:** Concurrent proposals A/B receive only relevant observations; unrelated feedback remains available; retry yields one link; no workspace-wide consumption.
- **29-B:** Task-only, personal preference, temporary exception, durable domain correction and unknown fixture classify appropriately; expired exception never published.
- **29-C:** Agent forged reviewer/actor/release rejected; cross-workspace read denied; unsupported correction cannot become evidence.
- **29-D:** Human PR addition, deletion and replacement captured once with correct scope/digest; unknown author labelled unknown; no follow-up loop for unchanged proposal.
- **29-E:** Rejected proposal and later new authoritative evidence reuse linked feedback without duplicating same active investigation.
- **29-F:** Secret/injection inputs do not reach model or Git; migration preserves legacy records and tests explain intentional behavior change.

Extend `internal/gaps/service_test.go`, `internal/workflows/human_test.go`, add `internal/feedback` tests and PostgreSQL concurrency fixtures. Run shared gates, update schemas/operations docs. **Done:** every learned correction has scope, authority and provenance; no unrelated signal loss.

## Non-goals

Personalised agent memory, general HR/user profiling, team ACL implementation or automatic knowledge approval.

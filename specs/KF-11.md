# KF-11 Trace intake

## Goal

Let the curator read a human correction from a trace, without copying secrets or obvious personal data into the proposal.

## Inputs / outputs

- `trace_ref` on a gap report is a filesystem path the operator supplied.
- The file is either `{"turns":[{"role","text"}]}` or a JSON list of OpenTelemetry GenAI attribute maps (`gen_ai.prompt.*`, `gen_ai.completion.*`, `gen_ai.human`).
- `internal/traces.ImportJSON` redacts secret-shaped text, emails, and phone numbers before `HumanAsks` returns human and user turns.
- `Steps.Prepare` appends those turns to the unread-feedback list the curator already sees.

## Non-goals

- Running the optional collector in `deployments/otel-collector.yaml`. The factory does not export traces.
- Fetching a trace from a remote collector. A missing or unreadable file is skipped.

## Definition of done

`go test ./internal/traces` passes. A readable `trace_ref` changes what `Prepare` passes as feedback. A secret-shaped span does not reach the curator as plaintext.

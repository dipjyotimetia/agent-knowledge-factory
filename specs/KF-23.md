# KF-23 — Stateless Temporal activities and concurrency

**Priority:** P0 · **Depends on:** KF-22 · **Enables:** all concurrent learning workflows

## Goal / baseline defect

`Steps` has mutable `lastBefore`, `lastAfter`, `targeted`, `Evidence` fields. The same registered activity object is used by concurrent workflows and a minute-ticker reconcile. `DrainOpenWorkflow` opens proposals directly and exits, so no per-gap workflow may be waiting for review. `Prepare` persists and consumes global feedback separately. Retries after external side effects can duplicate work. Eliminate shared mutable operation state and define recovery semantics.

## Inputs / outputs

`InvestigationInput{WorkspaceID,GapID,AttemptID,BaseReleaseID,PolicyVersion}` is immutable; validate workspace against worker config. Activity inputs/outputs carry IDs and safe reason enums. Persist `investigation_attempts`, `operation_ledger` (kind, key, request_digest, status, external_ref, attempt_count, error_code, lease expiry), `attempt_evidence` immutable links. Stage/receipt tables from KF-22 are reused. Store `EvaluationReceiptID`, `TargetCaseIDs` and before/after results keyed by attempt/release, never shared memory. A process-local `Steps` may hold only immutable deps/config; no per-run mutable fields or copied corpus in workflow history.

## Implementation sequence

1. Inventory `Steps` fields and all call sites, including CLI synchronous runner, worker, `DrainOpenWorkflow`, API signaling. Introduce attempt store and transactional claim (unique key, row lock/CAS, expired lease reclaim). Keep state transitions idempotent at service level: repeated logical transition returns previous receipt without duplicate audit; invalid transitions error. Persist output with state changes atomically where possible. Avoid holding DB transaction over network/model work.
2. Replace `RefreshEvidence` mutation with snapshot batch ID; `Prepare` reads exact batch for attempt. Candidate/target evaluation IDs are returned by activity or fetched from DB. No `lastBefore`/`lastAfter`/`targeted`. Read immutable complete release tree by ID. Different workspaces never share task payload state. Task queue configured per deployment/workspace or validate routing explicitly; no worker processes another workspace by mistake.
3. `DrainOpenWorkflow` schedules/starts same canonical per-gap workflow as immediate intake (deterministic child ID or activity calling starter); it must not independently call Prepare/Open. Stable workflow ID `curate-<workspace>-<gap>-<attempt>`; use explicit attempt lifecycle and unique live attempt per canonical gap. Duplicate intake joins attempt; transient retry same ID, terminal recurrence new linked gap. Schedule IDs scoped by workspace; bounded pages and continue-as-new for long history. Document overlap policy (skip if running), max concurrency and queue backpressure.
4. Implement retry-safe external side effects: deterministic PR branch includes attempt ID; find existing PR by exact repo/base/branch and verify expected content before reusing. Persist pending operation before call; if process crashes or times out after call, reconcile by external identity before repeat. Model requests without provider idempotency can be repeated only within budget; never claim exactly-once cost. Persist reservation before invocation. Retries for 429/5xx/timeouts with bounded backoff and jitter outside workflow randomness; validation/403/invalid policy nonretryable. Configurable review reminder/expiry (default 7d reminder, 30d park) via Temporal timers; parking retains PR and durable state, resume by explicit same attempt/new workflow signal rather than auto-reject.
5. Version workflows for outstanding executions; support old workflow signals until drained, or documented safe pause/restart with persisted PR mapping. Use `workflow.GetVersion` or new names; no breaking history replay. Replace minute-ticker publication with enqueue through KF-22; retention separate idempotent activity. Heartbeat long I/O, use context cancellation, maximum concurrency from config (default 4 investigations/workspace); enforce in DB or workflow coordination across worker replicas.

## Security and failure handling

Lease expiry cannot let stale workers commit output: fencing token monotonically advances; CAS includes token. No secrets or raw source bodies in workflow input/output/history/search attributes. No model calls in workflow. Audit operation IDs and safe reasons. Reject mismatched workspace/attempt even when UUID valid. Never log PR raw body or response payload. Cancellation does not mark verified or lose pending merge receipt.

## Acceptance criteria / tests

| ID | Required test |
|---|---|
| 23-A | Two investigations with different evidence/targets interleave using barriers; each obtains own receipt; `go test -race` clean. |
| 23-B | Refresh during prepare does not mutate attempt evidence; retry sees identical snapshot IDs. |
| 23-C | Duplicate schedule/intake across worker replicas creates one live attempt, one PR; schedule path receives review and completes. |
| 23-D | Simulate lost PR response and worker crash; recover exact PR by branch; mismatched contents fail closed. |
| 23-E | Lease expiry and stale activity cannot persist result; terminal error distinguished from retryable failure. |
| 23-F | Workflow replay tests for old and new histories; worker restart during review preserves signal handling; reminder does not auto-merge. |
| 23-G | Large corpus/trace is absent from serialized history; cancellation and task queue/workspace mismatch are rejected. |

Extend `internal/workflows/{workflow,cadence,start,steps,gate}_test.go`, add attempt store tests under PostgreSQL and live Temporal tests. Run race tests with concurrent activities, shared gates; document operational recovery, retry policy and upgrade strategy. **Done:** no shared mutable workflow state, no parallel curation bypass, no duplicate PR on retry, documented legacy workflow migration.

## Non-goals

Distributed lock service, changing Temporal provider, exactly-once LLM execution, or automatic human approval.

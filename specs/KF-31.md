# KF-31 — Incremental source connectors and drift detection

**Priority:** P2 · **Depends on:** KF-23, KF-28 · **Enables:** KF-32, 33, 34

## Goal / baseline

`EvidenceFromConfig` fetches pinned GitHub paths, one Notion page or Slack message. The budget is checked after network calls. `persistEvidence` assigns a single GitHub connection and updates immutable snapshot bodies. Implement incremental discovery and immutable provider-specific evidence; retain pinned mode. Detect drift, deletion and permission changes before unsafe knowledge can remain accessible.

## Interface / data model

`SourceConnector` methods: `Discover(ctx, Scope, Cursor, Limit) (ChangePage,error)`, `Fetch(ctx, ImmutableSourceRef) (Snapshot,error)`, `Metadata(ctx, SourceRef) (Metadata,error)`, `Permissions(ctx, SourceRef) (PermissionState,error)`. Source config includes stable `id`, provider, mode `pinned|tracked`, allowlisted repository/page/channel/path roots, `pin_sha` xor `tracked_ref` for GitHub, credential reference, server-assigned classification, explicit `workspace_shareable` default false, polling interval and max bytes/requests. No provider credential in API. `Change{source_id,location,version,kind:upsert|delete|permission-change,observed_at}`; cursor opaque provider value stored only server-side. `Snapshot` contains immutable version, source location, original-content digest (when policy permits), sanitised content digest, content, provider metadata, classification, permission proof/status, fetched_at. Source IDs namespace by workspace+provider+connection+location; avoid path-only collision. Extend `source_connections`, `source_snapshots` (immutable rows, unique connection/location/version; on digest mismatch reject rather than update), `source_checkpoints`, `source_changes`, `knowledge_source_links`, `source_access_state`, `revocation_events`. Backfill existing sources only when identity and permissions proven; ambiguous legacy snapshot is non-authoritative pending refetch.

## Implementation sequence

1. Extract connector interface and registry; adapt current GitHub/Notion/Slack fetchers. GitHub pinned mode immutable; tracked mode resolve configured ref once per scan to commit SHA, diff old/new trees or bounded listing, fetch by immutable SHA, handle rename/delete as tombstone plus add; non-fast-forward -> full bounded rescan and flag. Notion allowlisted roots/pages with pagination, revision/last edited and content digest; no unrestricted workspace search. Slack allowlisted channel/thread timestamps, bounded cursor/time window with overlap, handle edit/deletion where API exposes; do not infer deletion from pagination gap. Providers without reliable permission API require explicit operator shareability attestation with expiry, and recheck source access; unknown/expired permission is deny. Do not claim complete provider-wide deletion detection.
2. Scheduled `SyncSourcesWorkflow` per workspace/source; page changes, reserve budget before every HTTP request incl pages/retries, bounded timeout/max response, respect Retry-After; use checkpoint only after snapshot/change/tombstone/outbox commit. Stable batch ID captures consistent source revisions for investigation. No shared mutable evidence. Dedup same digest/version, reject immutable version conflict; provider revision missing use content digest with timestamp provenance. Retain source classification as config, not inferred by text. Record real provider identity/connection, remove hardcoded GitHub connection. Fetch secrets redacted before persistence/model; policy rejected content never stored.
3. Maintain reverse links from authoritative claim/knowledge item to exact snapshots, source and release; on changed source enqueue drift candidate with old/new digests and safe metadata. Changes don't automatically rewrite knowledge. Deleted/revoked source invalidates candidate receipts and provenance; if shareability/access lost, synchronously mark affected active items unavailable (filter by source_access_state in public read transaction; later KF-33 refines lifecycle), increment publication generation to fence stale promotion, hold if necessary. No unsafe cached reads. Unknown/permission check expired deny impacted items. Reconcile approved remediation through Git; do not remove source audit trail beyond retention/deletion rules. Old content must not be served even if rollback points to it. Store tombstone and remove restricted retained bodies as policy demands. Distinguish transient error from confirmed deletion: access unknown denies content, retry; no synthetic authoritative deletion.
4. Harden HTTP transport: HTTPS allowed host list, port/path scope, reject credentials in URL, no redirects to unapproved host, SSRF/DNS rebinding defence (resolve/connect to vetted addresses, block private/link-local/metadata unless explicit dev fixture; never send token across origin), size cap/streaming, safe errors. TLS required outside dev. Provider rate limits and partial failures per source; no cross-source checkpoint skipping. Tests fake HTTP endpoints only. Config `sources[].mode`, permission attestation, request limits; operator `kfactory sources sync/status` and metadata-only list, audit and metrics lag/errors/revocations.

## Security / failures

Credentials least-privilege read-only; no writes to evidence repos. Only explicit workspace-shareable source snapshots enter curator/model and published index. No ACL claims without actual provider proof or explicit scoped attestation. Permission loss fails closed before re-promotion; no raw external bodies in Git or workflow history. Do not log cursor/token. Secret-bearing snapshot reject. Model cannot select arbitrary endpoint or elevate classification. Retention includes snapshot bodies and provider deletion requests; preserve minimal receipts where permitted.

## Acceptance criteria / tests
- **31-A:** GitHub tracked ref moves A→B; immutable snapshot A unchanged, B fetched once, deletion/rename creates tombstone/drift; pinned source remains A.
- **31-B:** Notion paginated pages and Slack overlapping pages dedup; interruption before checkpoint retries exactly; 429 backoff bounded and no skipped data.
- **31-C:** Same path from two sources doesn't collide; same version/different digest rejected; correct provider connection stored.
- **31-D:** Budget zero/exhausted prevents next HTTP call; unsafe host, redirect, oversized response, invalid credentials and malicious content rejected.
- **31-E:** Revocation/unknown permission blocks affected published reads and staged promotion immediately, including stale cache/rollback; unrelated shareable knowledge stays accessible.
- **31-F:** Cross-workspace and source scope enforcement, secret sentinel absent; deletion purge and audit proof; provider outage recorded not falsely marked deleted.
- **31-G:** Existing pinned banking demo works, tracked synthetic fixture produces one drift candidate; no live dependency in CI.

Extend `internal/ingestion/{github,notion,slack}`, add connector registry, source store and scheduled workflow tests; PostgreSQL revocation race tests; update example config and source runbook. Run shared gates. **Done:** incremental, bounded, immutable and permission-aware discovery.

## Non-goals

Dozens of additional connectors, full enterprise search, per-user ACL search, raw production data replication, automatic source updates.

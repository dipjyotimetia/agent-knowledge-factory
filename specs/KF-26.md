# KF-26 — Experience ingestion and trace normalisation

**Priority:** P1 · **Depends on:** KF-24 · **Enables:** KF-27, 29, 35, 37

## Goal / baseline

The current `internal/traces` parser extracts human/user messages from small JSON documents. It does not continuously ingest executions or correlate knowledge use with task outcomes. Create a provider-neutral, privacy-preserving experience store. Experience is a hypothesis input, never authoritative knowledge.

## Inputs / outputs and schema

Define `ExperienceEnvelopeV1` with `schema_version: 1`, `client_event_id`, `run_id`, `event_type`, `occurred_at` (RFC3339 UTC), `sequence` (nonnegative), optional `trace_id`, `span_id`, `parent_span_id`, `task_kind`, `knowledge_refs` (URI + release SHA), `tool_name`, `outcome`, `duration_ms`, `input_tokens`, `output_tokens`, `error_code`, and `attributes` (typed allowlisted metadata). Types: `run.started`, `knowledge.retrieved`, `knowledge.used`, `tool.completed`, `human.corrected`, `run.completed`. Outcomes: success/failure/cancelled/unknown. Correction body optional, sanitised and bounded to 2 KiB; never require full transcript. Server assigns workspace/actor/received_at/UUID. Run start captures model/agent/tool-config version and active revision; if unreported use unknown, do not invent. An event referring to a release records observed provenance, not proof of actual use. `run.completed` includes independent task result/check reference when available.

Add `experience_events` (unique workspace+actor+client_event_id, payload digest), `experience_run_summaries` or additive `agent_runs` fields (actor, status, first/last times, metadata, completion source), `experience_knowledge_links` and `ingestion_receipts`. Every link workspace-scoped. Trace record from KF-24 stores optional sanitised turn data; no duplicate raw payload. Define `POST /v1/experience/events` agent role, batch max 100 events / 1 MiB; return per-event receipt ID/status `accepted|duplicate|rejected` with safe reason; entire invalid envelope or quota error rejects batch, valid batch persists valid events atomically with rejection statuses (document partial processing). `kfactory experience import --format native|otel-json --file ...` local operator adapter. API accepts native envelope only in V1; OTLP collector adapter converts selected GenAI attributes/spans locally into envelopes, do not expose raw OTLP on factory. Record unsupported fields as count, not value. Ship example envelope/schema and compatibility tests.

## Implementation sequence

1. Define typed domain events, JSON schema with strict known fields/enum/range checks and version dispatch. IDs max 128, task/tool names max 128, references max 20; reject oversized payloads pre-decode, nonfinite numbers, future timestamps beyond configured clock skew (default 5 min), invalid trace IDs; historical import permitted within retention. Avoid unknown nested objects and unbounded cardinality. Native timestamps are source claims; use received_at for ingestion ordering/retention.
2. Implement adapter for existing trace JSON and OTel GenAI attributes/spans; preserve order by sequence and span timestamps, deterministic tie-breaker; do not iterate Go maps to infer conversation order. Map known conventions to types, do not guess task outcome from text. Unsupported or ambiguous spans map unknown. Preserve correlation only, not prompt/completion/tool args by default. Pin convention mapping in docs with fixture samples; no mandatory external collector.
3. Redact/drop sensitive fields before persistence, model, logs or workflow history. Use structured allowlist + existing policy scans, reject unsafe free text, strip customer identifiers and credentials. Explicit opt-in correction text only for allowed workspace; synthetic fixtures only in repo. Validate same run and actor for events; out-of-order events may create incomplete summary, later reconcile; conflicting duplicate completion never overwrite prior terminal outcome silently. Aggregate summaries from immutable events by deterministic reducer; mark completeness and `outcome_source`. No automatic status inference from absence of error.
4. Implement store/batch transaction, idempotency and quotas (default 100 events/min/actor, configurable); duplicate payload same key returns same ID, different digest conflict. Sequence duplicates conflicting event types flagged; permit delivery reordering. Use cursor `(received_at,id)` for consumers; no event lost across retry. Post-commit outbox or scheduled scan for downstream KF-27. Retention deletes sanitised content and summaries as required; keep minimal audit receipts only. Backfill existing run rows with `unknown` status, not success.
5. Wire HTTP/CLI, config `experience.enabled` default false, `max_batch_bytes`, `max_events_per_batch`, `allow_correction_text` default false, rate and retention. Expose metrics accepted/rejected/duplicate/unknown, ingestion lag and backlog; no IDs or payload labels. Provide operator docs on enabling and disabling ingestion; stdio remains compatible.

## Security / failures

Agent submits only own run under authenticated identity. No request-controlled network destinations or file paths. IDs not credentials. Cross-actor/tenant links denied. Untrusted correction text cannot become evidence or execute. Fail closed when auth/sanitiser/store missing. Request cancellation returns retryable failure; duplicate retry cannot double-count. Never persist rejected raw bytes. Explicit disabled route returns 503/404 documented; no anonymous ingest.

## Acceptance criteria / tests

- **26-A:** Native batch and equivalent OTel fixture produce same semantic events and ordered summary; missing outcome remains unknown.
- **26-B:** Reordered starts/completion and duplicate delivery yield deterministic run; conflicting idempotency key 409, no new event.
- **26-C:** Two agents/workspaces cannot attach events to each other's run or trace; RLS tested with app role.
- **26-D:** Oversize, unknown schema, invalid timestamps, secret-bearing and malformed attributes rejected or redacted before storage; sentinel absent from logs/DB/history.
- **26-E:** Batch failure/retry, rate limits and disabled ingestion behave as documented; retention removes expired payload and links.
- **26-F:** Knowledge revision/usage, tool result and independent task outcome available to downstream consumers; no automatic proposal or publish.

Add `internal/experience/{domain,normalise,store,service}_test.go`, `internal/api/experience_test.go`, schema tests, fixtures under `examples/banking/`. Run shared gates; migration and privacy guide required. **Done:** reproducible normalised events and safe queryable summaries without raw trace retention.

## Non-goals

Full observability backend, OpenTelemetry server, streaming broker, storing production transcripts or automated learning in this spec.

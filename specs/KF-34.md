# KF-34 — Retrieval improvements and context assembly

**Priority:** P2 · **Depends on:** KF-24, KF-32, KF-33 · **Enables:** KF-35, 37

## Goal / baseline

Current PostgreSQL full-text search and 64-dimension hashed-token reranker operate on top lexical hits; no semantic recall improvement beyond lexical pool. Introduce measurable retrieval quality and deterministic context assembly while preserving approval, lifecycle and workspace isolation. No mandatory vector infrastructure.

## Contract

Keep existing `knowledge.search/get` compatible. Add `SearchRequest{query,type,limit,domain,task_kind,release_session_id?}`; limit 1–20 default 10, bounded query 200 chars (legacy), optional filters validated. `SearchResponse{release_sha,release_id,policy_version,results[]}`; results include URI, type, title, snippet, rank, safe source refs, trust tier, stale warning, last_reviewed, optional matched section ID; no raw score interpreted as confidence. `knowledge.context` returns `ContextBundle{release_sha,items[],citations[],warnings[],budget_used,omitted_count}` for query/task kind, types (concept/skill/data-access), token_budget 256–8000 default 2000; section-level text excerpts with URI+revision+section+source IDs, not unbounded whole corpus. No execution of skill/data contract. Public reads active only; session pin = active SHA at start, if active revision changes return `revision_changed` 409/tool error and require restart, not historical reads. Internal replay/candidate reader can pin private namespace by authorised evaluation ID (KF-35). Recheck revocation/expiry on every query; no stale session bypass.

## Implementation sequence

1. Create `internal/retrieval` abstraction around `PublishedReader`/`CandidateReader`. Filter workspace/active release, stable/approved status, current lifecycle and permissions in SQL before ranking/count; no post-filter leak. Add deterministic section indexing (heading path, ordinal, body digest, parent URI; bounded max 2 KiB or configurable), stable tie-break URI+section ordinal, exact symbol/identifier match boost for gRPC/Avro/API fields, title/heading weighting, domain/type filtering. Keep full-text baseline. Separate section retrieval from whole item get; maintain stable citations across same revision. Candidate and active use same ranking/config, separate data visibility.
2. Compare lexical, existing hash reranker and optional true vector path against fixture benchmark. Hash is token similarity not semantic embedding; name accordingly. Optional pgvector mode only if extension and provider configured; default off; explicit provider data policy, embedding model/version/dimension and content digest per row, independent candidate pool + rank fusion (e.g. RRF k=60), filter before fusion. Never silently fall back while labeling vector mode active; if provider unavailable use documented lexical fallback with warning or configured strict fail. Do not add mandatory DB extension or cloud call. Benchmark must report dataset, mode, latency, recall and limitations; adopt vector only if improves held-out retrieval or clear ADR.
3. Context assembler selects top distinct items/sections, dedups overlapping text, adds directly referenced approved skills/contracts when relevant within same active release, preserves source provenance and warnings, explicit budget estimate based on UTF-8/text tokenizer (document conservative estimate, no exact token claim without tokenizer). Reserve overhead for citations; truncate only at safe section boundaries, emit omitted_count, never omit critical caveats while including advice (skip section if cannot fit). Unknown/conflicting/withdrawn knowledge -> no unsupported answer, warning/abstain. Return text as untrusted context, not system instructions. No model call required. Cache optional only keyed workspace/release/policy/generation/query/mode, invalidated on revocation; prefer no cache initially.
4. Add benchmark dataset under `examples/banking/tests/retrieval-cases.json`: >=30 synthetic labelled queries (identifier, paraphrase, ambiguous, no-answer, stale/revoked, multiple domains), relevant URI sets and expected abstentions. Compute Precision@k, Recall@k, MRR, nDCG@k optional, no-answer false positives, stale/withdrawn exposure, p50/p95 latency; report exact denominator and no-answer separately. Distinguish ranking vs answer correctness. Use deterministic CI fixture, compare baseline vs candidate and fail if critical regression or any forbidden hit. Initial acceptance: critical Recall@5 non-decreasing, MRR non-decreasing on held-out set vs baseline, forbidden exposure 0; latency baseline measured in same environment, no invented SLO. Update KF-22 candidate gate to use actual candidate index and same config.

## Security / failures

No retrieval of staged, historical inactive, expired critical, withdrawn or restricted knowledge through query/filter/citation/context, including counts. Prompt injection in content remains untrusted, no automatic tool call. No raw query text with secrets; existing redaction preserved. Vector provider optional explicit data approval, no secret embedding; deny unsafe source. Limit query length/complexity and section counts, SQL parameters, timeout. Unknown type/filter invalid; no hidden widening of scope. Revision changes explicit retry.

## Acceptance criteria / tests
- **34-A:** Relevant sections ranked deterministically for identifier/paraphrase; domain/type filters and citation spans exact; candidate/active identical algorithm.
- **34-B:** Private/revoked/expired/cross-workspace results absent before counts and fusion; explicit stale session fails; no cache leak.
- **34-C:** Context budget enforced, references deduped, critical warning not truncated; no skills/scripts/data queries executed.
- **34-D:** New/deleted/reordered docs change candidate scores and gate detects regression; benchmark outputs exact per-query metrics and denominators.
- **34-E:** Optional vector absent/misconfigured/provider failure documented fallback/strict failure; no mandatory extension; embedding cache version invalidation tested if implemented.
- **34-F:** Existing clients work with additive fields; MCP supports data-access filter/context; no-answer case avoids irrelevant result according to configured threshold.

Add retrieval/benchmark tests, extend `internal/index`, `internal/evaluations`, MCP/API and RLS tests. Run shared gates; document benchmark command and actual results when implemented. **Done:** measurable retrieval and revision-safe bounded context, no security regression.

## Non-goals

Hosted vector DB, mandatory LLM reranking, full knowledge graph, agent task execution, personalised cross-workspace memory.

# KF-28 — Bounded agentic curator

**Priority:** P1 · **Depends on:** KF-23, KF-27 · **Enables:** KF-29–34

## Goal / baseline

`curator.RulesByName` resolves a banking-specific rule and `model.Propose` sends only summary and source blocks, ignoring existing knowledge, observed/expected, suggested edits and feedback. `tokenGrounded` accepts a backtick token occurrence, not entailment. Replace primary rule-only curation with bounded evidence investigation while retaining deterministic validators and reviewer approval. Do not turn curator into unrestricted coding agent.

## Interfaces / outputs

`InvestigationContext{AttemptID,WorkspaceID,BaseReleaseID,GapID,PolicyVersion,AllowedSourceIDs,ExperienceIDs,FeedbackIDs,Budget}`; `Curator.Investigate(ctx,context) (ProposalDecision,error)`. Decisions `update|create-skill|no-change|insufficient-evidence|escalate`; retain existing enum compatibility, add new item creation only through allowed edit types and schema migration if needed. Structured proposal includes exact base SHA/tree digest, operations (create/replace/delete with relative path, old digest, new content or bounded patch), per-claim `subject,predicate,value,scope,evidence_spans[]` (snapshot ID, digest, byte/line range, exact quote hash), rationale, uncertainty, affected knowledge URIs, targeted evaluation intent, feedback/experience IDs, risk, budget use and abstain reason. No raw chain-of-thought requirement; store concise evidence-backed decision summary. Existing `schemas/proposal.schema.json` versioned with compatibility; legacy model adapter only accepted via new validators.

Allowed investigation actions are typed service methods: `search_knowledge(query,type,limit)`, `read_knowledge(uri,base_release)`, `list_allowed_sources(scope)`, `read_evidence(snapshot_id or configured_source_ref)`, `read_experience(id)`, `read_feedback(id)` (KF-29), `propose_patch`, `abstain`. No shell, arbitrary URL, credentials, general MCP proxy, external writes, source modification or merge. Before KF-31 source discovery limited to configured snapshots. Implement internal tool dispatcher; model calls inside Temporal activities, inputs are IDs. Deterministic mode supports explicit configured contract extractors for CI; do not default banking rule in general production config.

## Implementation sequence

1. Add typed investigation state machine: gather relevant gap/knowledge/evidence/context → plan bounded queries → inspect allowed results → synthesise → validate → proposal/abstain. Read pinned release not mutable root. Include gap observed/expected, suggested edit, relevant existing knowledge excerpts, trace/feedback summary, authoritative source descriptions with trust/scope and stable IDs. Label all external text untrusted; never concatenate secrets, raw traces or golden evaluation answers. Use provider interface and strict JSON schema; reject unknown tools/fields, malformed output, unsupported decisions. No free-form model-generated tool execution. Deterministic validators check every action, not just final result.
2. Durable budget ledger per attempt; defaults 4 model calls, 20 source fetches, 8,000 total input+output token budget, 10 tool steps, 2 min wall time, 64 KiB evidence/context (configurable hard maxima). Reserve before call, use conservative token estimator and max output, reconcile provider counts, count failed calls/retries, never exceed allowed calls/fetches. Enforce limits before network requests incl pagination; stop with `budget-exhausted` abstention; no silent truncation of evidence that changes meaning. Provider may report unexpected tokens: flag/stop subsequent calls; document billing uncertainty. Limit concurrency via KF-23. Model off/unavailable -> deterministic safe mode or insufficient evidence, never fabricate proposal.
3. Ground edits: every new normative claim linked to exact authoritative, shareable source span; validate span bounds/digest/content and scope. Full proposed file diff maps claims to changes, reject unsupported extra sentences. Deterministic exact/schema extractors verify supported facts; for ambiguous semantic claims require explicit reviewer acknowledgement with evidence and do not claim automated entailment. Token occurrence alone cannot authorise an edit. If conflicting authoritative sources, escalate; if only secondary/experience evidence, request human confirmation/authoritative source. Check path allowlist, base digest, per-file/total size, duplicate/conflicting edits, secret/PII and script execution prohibition. Require candidate evaluation via KF-22 before PR. A missing test mapping allows publication only under existing policy but not verification.
4. Persist immutable attempt action ledger with action type, input/output digests, evidence IDs, duration/token counts, outcome (not hidden reasoning/raw prompt). Use `operation_ledger` and scoped evidence batch. Return proposal ID, not file bytes in workflow history. Keep deterministic `BankingDedupeRule` as plugin/validator; tests prove another domain works without code changes (config/schema extractor or mocked model). Document model config, cost, supported provider interface and prompt version.

## Security / failure handling

Prompt injection in evidence/feedback treated as content; tools independently enforce workspace, allowed source/host and rate limits. Provider cannot select new privileges or access credentials. Never execute code/script generated in proposal; only validate inert bytes. No secret or unapproved source output to external provider; explicit model enablement and workspace data policy. Refuse if provider unavailable or policy disallows data transfer. Failure and budget exhaustion are visible, no automatic approval.

## Acceptance criteria / tests

- **28-A:** Mock provider investigates a non-banking gap using existing knowledge, observed/expected and source spans; generates valid reviewable proposal; no golden answers in model inputs.
- **28-B:** Malicious source asks for shell/URL/merge or secret disclosure; tool dispatcher denies, final proposal rejected/abstains.
- **28-C:** Correct token but false surrounding claim, mismatched digest/span, secondary-only evidence, conflicting policies, stale base or path traversal cannot pass.
- **28-D:** Budget counted before fetch/model; retries and provider token overage stop, never extra calls beyond cap; restart resumes safely.
- **28-E:** Invalid model JSON/tool/decision, cancellation, 429 and unavailable provider handled with bounded retry or abstention; no unsafe edit.
- **28-F:** Valid deterministic banking flow remains; second domain uses no hardcoded banking path; PR gates still mandatory.
- **28-G:** Scope isolation and audit/ledger proof; no raw prompts/trace content in history/log/PR metadata.

Add `internal/curator/investigation_test.go`, `internal/model/*_test.go`, validation/schema/fake provider tests and Temporal budget/restart integration. Run shared gates. **Done:** bounded investigation, claim-level provenance and safe abstention across domains.

## Non-goals

Training models, open-ended autonomous agents, general-purpose tool execution, automatic semantic truth guarantees or PR merge.

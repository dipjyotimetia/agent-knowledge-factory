# KF-01 Bootstrap

## Goal

A contributor can start Postgres and Temporal with one command, run deterministic tests, and see a workspace-scoped control API with a separate installer database role.

## Inputs / outputs

- Inputs: config file, environment variables, SQL migrations.
- Outputs: `factoryd` health and readiness, `GET /v1/workspace` for the authenticated workspace, `kfactory init`, an idle `factory-worker`.

## Non-goals

- Parsing OKF or skills (KF-02).
- Fetching GitHub (KF-03).
- Search, MCP tools, gap intake, curation, or evaluation.

## Interfaces

- `GET /healthz`, `GET /readyz`
- `GET /v1/workspace` with `Authorization: Bearer`
- PostgreSQL schema in `migrations/001_init.sql`, including forced row-level security
- `kfactory version` and `kfactory init`

## Failure modes

- Missing database: `/readyz` returns 503 and the process logs the driver error without returning it to the client.
- Token for workspace A plus `workspace_id` of workspace B: 403, and the store is not queried with B.
- API database role: `CreateWorkspace` is refused. Installer migrations are refused on a non-installer connection.
- `AKF_DEV` unset: sample dev tokens are not loaded.

## Tests

- Workspace id validation.
- Config loading, including the dev-token gate.
- Bearer authentication and cross-workspace rejection.
- Migration plus row-level security against PostgreSQL: a transaction scoped to A cannot read B, even without a `WHERE` clause.
- JSON Schema examples for the gap report and the proposal.

## Definition of done

`make dev-up` is defined for Postgres 18, Temporal 1.29.1, and `factoryd`. `make test` passes vet and `go test -race`. CI runs the same tests against the Postgres 18 service. ADRs 0001–0005 and the two contract schemas are in the tree.

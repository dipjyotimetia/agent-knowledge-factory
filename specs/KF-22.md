# KF-22 — Unified publication and reconciliation

**Priority:** P0 · **Depends on:** baseline · **Enables:** KF-23–25, KF-35

## Goal and baseline defect

Make every active revision change use the same fail-closed, auditable release process. `runtime.NewReviews` constructs a `Steps` without `CasesPath`; push reconciliation can bypass evaluations. `gate.verifyOpenGaps` advances any open gap with a proposal regardless of whether its PR merged. `vetProposal` overlays old search hits, so cannot detect rank/new/deleted-item regressions. `Publish` requires exact default-head equality, which fails on legitimate later merges. Local tree overlays and forge snapshots are not guaranteed to represent a complete candidate tree.

## Inputs / outputs and contract

Introduce `internal/publication` with service interfaces (names may adapt to existing packages): `RequestRelease(ctx, ReleaseRequest) (OperationID,error)`, `EvaluateCandidate(ctx, CandidateID) (Receipt,error)`, `Promote(ctx, ReleaseID, ExpectedGeneration) (Receipt,error)`. Request contains trusted workspace, trigger (`pr-merge`, `push`, `reconcile`, `bootstrap`, `operator`), repo identity, branch, optional proposal/PR ID and observed SHA. Receipt includes base active SHA, candidate tree digest, resolved Git SHA, evaluator/policy/dataset digests, outcome, timestamps and reason. `release` is a verified Git tree; private pre-PR candidate is never itself a release. Return pending receipt on accepted durable enqueue, not publication success.

Add tables `publication_operations`, `knowledge_releases`, `publication_receipts`, `proposal_merge_links` and workspace generation. Unique release identity `(workspace,repo,git_sha,tree_digest,policy_digest,dataset_digest)`; unique merge link `(workspace,proposal_id,pr_number,merge_sha)`. Track queued/validating/staged/rejected/promoted/superseded; link receipts by exact candidate/base and policy revision. All migrations obey guide. Never mark all gaps verified in a bulk query.

## Implementation sequence

1. Expand read-only forge capabilities: resolve configured default ref; read complete immutable tree including deletions (not overlays); fetch PR by number including repo/base/head, merge result and review status; check commit ancestry. Memory/directory adapters implement equivalent deterministic semantics; directory mode requires explicit dev/operator fixture, never masquerades as GitHub approval. Validate exact repo/branch/installation identity, not just branch name. Extend `CreatePullRequest` with expected base SHA and reject stale base before opening; use current published/approved immutable tree, not mutable `KnowledgeRoot`.
2. Funnel webhook PR/push, periodic reconciliation, review signal, CLI indexing/bootstrap and publish path into durable enqueue. `Reindex`, `Promote`, `SyncDelivery` must not provide unauthenticated bypass; restrict mutation to internal release service or explicit dev fixtures. Validate webhook HMAC, payload size, event identity, PR mapping; persist event and outbox in one transaction, dedupe by delivery ID. Poll/retry pending operations after restart; acknowledge only after durable commit. Reconciliation reads actual default head, never treats event payload as authoritative.
3. Validate full candidate: path/size/type safety, OKF/skills, secret scans, claim/evidence and source-scope policy, required case suite. Production must reject missing/empty required gates. Build private index from exact full tree; evaluate against pinned baseline and candidate, including ranking, addition/deletion; use isolated candidate reader (KF-24 hardens this). Test the same gate before PR, on revised PR head and on actual merged tree; re-evaluate if base/head/dataset/policy changes. `RunDecisions` on fixed inputs is a curator unit gate, not a candidate regression test. Persist separate metrics with actual revisions and consistent counts. Before KF-35 use explicit gap↔retrieval case mappings; don't claim execution improvements.
4. Promote transactionally only with successful immutable receipt, current generation, matching baseline and no invalidation. Lock workspace row or CAS; concurrent update causes re-evaluation from new base. Recheck default head/ancestry immediately before promotion; reject divergence/force push pending reviewer/operator investigation. If head advanced normally, enqueue newest head; do not require PR merge SHA equal head. Full tree digest must match receipt; staging never rewrites active rows. Reconcile later Git changes safely. A crash after pointer commit must be recoverable from persisted receipts and outbox.
5. For each linked proposal independently verify actual PR merged into default history (squash/rebase supported via forge-reported merge identity), expected final changes still present or reviewer-approved adjusted diff, then move accepted→published. Mark verified only when explicit targeted failed-before/passed-after cases linked to that gap and candidate prove improvement; missing test leaves published. Rejected/other open PRs unaffected. Persist proof and actual revision; no inference from same repo or same branch prefix. Recover missed review events even when pointer already current. Capture human review deltas only for the corresponding PR.

## Security boundaries and failure handling

Agent/reviewer requests cannot publish or supply trusted SHA/evidence. Missing forge proof, policy, suite, revoked source, malformed tree, transient error or regression leaves active release unchanged. Review API is a hint, not proof of merge. Never merge from worker. Signed webhooks from another repo rejected. Payloads/patches in private storage are bounded, redacted; audit IDs and decisions. Reconciliation must not mark a proposal accepted based on untrusted branch text. Use generation fence in KF-25.

## Acceptance criteria / required tests

| ID | Testable behaviour |
|---|---|
| 22-A | Push, PR review, periodic reconcile and CLI all invoke the same gate; invalid case suite blocks promotion through each path. |
| 22-B | Two PRs, only A merged: B remains awaiting-review; A published but not verified without targeted proof. |
| 22-C | Merge A followed by B before webhook: ancestry and actual tree checked; reverted A is not verified. Missed delivery recovers without re-promotion. |
| 22-D | Candidate adds/removes/renames/reranks a knowledge item: real candidate search detects regression; unchanged active bytes and SHA on reject. |
| 22-E | Invalid signature, repo, PR mapping, traversal, stale base, force-push divergence, absent evaluations fail closed. |
| 22-F | Duplicate/out-of-order webhooks, failure after enqueue, after stage and after pointer commit: one logical release receipt and correct gap status. |
| 22-G | Concurrent CAS conflict forces fresh baseline; no older candidate overwrites newer approved release. |

Add `internal/publication/*_test.go`, extend `internal/workflows/gate_test.go`, `internal/api/webhook_test.go`, `internal/index/index_test.go`, `internal/demo/banking_test.go`; live PostgreSQL integration for CAS and outbox, fake GitHub HTTP for PR/ancestry. Preserve existing tests or change assertions only where superseded behaviour is unsafe. Run shared gates. Update architecture/ADR publication paths and bootstrap runbook. **Done:** all seven IDs demonstrated with persisted evidence, no alternative production pointer mutation. Deploy only after KF-23–25.

## Non-goals

No auto-merge, graph DB, external scheduler, full agent execution evaluation yet, or redesign of Git knowledge format.

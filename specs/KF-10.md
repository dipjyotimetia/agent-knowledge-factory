# KF-10 Banking demo

## Goal

Prove one learning cycle on the movement-lifecycle dedupe guide without modifying `distributed-systems`.

## Inputs / outputs

- Stale knowledge in `examples/banking/fixture-knowledge`.
- Recorded contract bytes from `distributed-systems` commit `8e6680d683ac728f0f089bd60e4a96576ab4ed45`.
- Two agent reports, one investigation.
- A human merge on the in-memory forge.
- After publish, retrieval of the dedupe key is `eventId`. A rollback reindex restores `movementId`.

## Non-goals

- A live GitHub App, a live model, or an edit to the banking repository.
- OpenTelemetry intake.

## Loop

1. Index the fixture. The critical eval case fails because the guide says `movementId`.
2. Two agents report the same gap. One canonical investigation links both.
3. The deterministic curator reads the recorded README and Avro schema and proposes replacing `movementId` with `eventId`.
4. A pull request opens. Default search is unchanged.
5. A forged merge SHA does not publish. `HumanMerge` does.
6. The critical case passes and previously passing critical cases do not regress. The gap becomes `verified`.
7. Reindexing the original tree rolls the guide back to `movementId`. Repeated webhook delivery is covered by KF-04.

## Definition of done

`go test ./internal/demo` passes. `make test` passes. README explains the GitHub App, tokens, and branch protection the owner must configure before any live call.

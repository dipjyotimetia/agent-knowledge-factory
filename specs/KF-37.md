# KF-37 — Streamable HTTP MCP and agent SDK

**Priority:** P2 · **Depends on:** KF-24, KF-26, KF-34 · **Enables:** KF-38

## Goal / baseline

Existing MCP is stdio, workspace-bound process configuration, five tools and resource template. Add secure remote MCP for multiple agents and a small Go SDK without changing trust boundary. Do not expose curator or publication mutation tools. Preserve stdio and existing control API.

## Protocol and API contract

Use installed `github.com/modelcontextprotocol/go-sdk` Streamable HTTP server/client capabilities; inspect version and supported protocol revision, pin in ADR, upgrade only if necessary. Endpoint `/mcp` (POST/GET/DELETE according to supported Streamable HTTP implementation), default disabled `mcp.http.enabled: false`, bind through existing HTTP server or explicit listener. Prefer stateless server mode if SDK supports required capabilities; otherwise sessions random >=128-bit, expiry default 30 min idle, bound to authenticated principal/workspace/actor and protocol version, bounded max sessions; never accept session ID as authentication. Support initialize/capability negotiation, JSON-RPC errors, tool calls, resources; SDK handles protocol, do not hand-roll. No legacy SSE endpoint unless explicitly necessary/documented; no promise of unsupported resumability. Existing tool names unchanged: `knowledge.search`, `knowledge.get`, `knowledge.report_gap`, `knowledge.submit_feedback`, `knowledge.get_gap_status`; add `knowledge.context` from KF-34 and `experience.submit_events` bounded batch from KF-26 (agent own run). Published resource `kb://{authority}/{path}` resolves same workspace and active revision, reject mismatched authority and unsafe paths. Tools never take trusted workspace/actor from model; supplied optional workspace must match. No arbitrary source search/PR/merge/rollback tool.

Remote auth: production use standards-compliant MCP HTTP authorization profile for supported version (OAuth 2.1 resource server, protected resource metadata, issuer/audience validation, scopes, TLS; verify current spec when implementing). Integrate configured external issuer/JWKS/introspection as appropriate, no built-in identity provider or dynamic registration implementation. Map verified subject/client to workspace+actor+role through trusted config or signed claims with configured issuer, audience and allowlist. Scope `knowledge:read`, `knowledge:report`, `experience:write`; default deny unknown scope. Existing static bearer tokens allowed only explicit dev/local trusted mode, not described as OAuth compliant. If full supported profile unavailable, keep remote production disabled and document blocker; do not silently downgrade. Every HTTP method/request authenticated before SDK handler, including session resume and resource reads. Origin header validation against explicit allowlist; reject invalid origin, restrict localhost/dev; TLS termination documented, trust proxy headers only configured proxy. No wildcard CORS credentials.

SDK package `sdk/go/akf` (same Go module unless ADR separate version): `Client` constructed with `baseURL`, auth token provider, HTTP client/timeouts, optional transport selection (MCP remote or existing API where supported). Typed `Search`, `Get`, `Context`, `ReportGap`, `SubmitFeedback`, `GapStatus`, `SubmitEvents`, `WithRun` helper returns stable run ID/idempotency events. Reuse domain/schema types via public DTO package, not import `internal` from downstream; no generic privileged tool proxy. Context cancellation, typed safe errors, retries only idempotent requests with same client_event_id; no automatic revision change mid-task, return revision_changed; token provider refresh via caller, never persist token. Example minimal agent using synthetic data and mock transport.

## Implementation sequence

1. Review SDK protocol support and auth requirements; write ADR with selected version, supported methods/session model, threat model, config defaults. Refactor MCP handlers to derive principal per request/session rather than process-wide agent ID; stdio trusted local principal remains fixed config. Share business services/validators for both transports; no duplicate logic. Fix fail-open control API registration when auth missing (protected routes deny by default). Add role/scope checks and workspace binding before any read/report.
2. Mount Streamable HTTP handler behind auth, origin, request size (default 1 MiB), rate (60 tool calls/min/actor configurable), timeout/cancellation, request ID and safe audit. Limit concurrent sessions/calls (default 10 per actor), per-tool bounds. Validate Content-Type/Accept/method per SDK; handle session expiry and mismatched identity as generic 404/401. GET event stream if supported auth on every connection, bounded duration; no session shared across principals even with guessed token. No sensitive query parameters, request/response body logging, credentials in URL. Health/readiness indicates enabled/configured status without leaking issuer secrets.
3. Wire SDK DTOs and MCP tool calls; stable idempotency IDs for mutating submit operations, document legacy feedback no client ID; return safe typed errors and receipt/revision. Example client reports gap and run outcome, reads context, handles revision change. Publish package docs and `examples/sdk/` synthetic sample. No new mandatory dependency for stdio clients. Test SDK with httptest and fake issuer/key rotation; no external auth in CI. Document TLS/reverse proxy, OAuth resource metadata discovery, token scopes and migration from stdio; do not recommend exposing dev bearer mode publicly.
4. Add remote conformance tests for negotiated SDK version, initialize, list tools/resources, call/read, session/auth/origin/method/error behavior, duplicate event, rate limit and cancellation. Cross-workspace tests on real DB. Keep production flag off until auth conformance and wave-A safety gates pass. Include opt-in integration with real issuer only if credentials available; report skipped, not passed.

## Security / failures

Treat remote server as network-facing. Missing auth/issuer/TLS/origin config fails closed. Verify token signature, issuer, audience, expiry, scope and principal mapping; reject token intended for another resource, no token passthrough to downstream source/provider. Protect JWKS fetch host, bounded refresh, fail closed on invalid/unknown key. Session bound to principal on each request, no auth by session alone. Agent tools read active approved knowledge only, never candidate or raw evidence; no merge/execute. SDK retries bounded 429/5xx only when idempotent, no retry forbidden/invalid, no leaking tokens in errors. Avoid request smuggling by using standard HTTP server/proxy config.

## Acceptance criteria / tests
- **37-A:** Disabled default; enabled remote initialize/list/call/read with valid scoped auth works; existing stdio tests unchanged.
- **37-B:** Missing/expired/wrong issuer/audience/scope token, untrusted origin, invalid session, cross-actor/workspace and unsupported method rejected before tool invocation.
- **37-C:** Guessed SHA/candidate/resource URI cannot bypass active revision; revision_changed handled; no privileged tools exposed in list.
- **37-D:** Duplicate report/events via SDK retry produce same receipts; cancellation, timeout, quota and session expiry handled without resource leak.
- **37-E:** TLS/auth config missing fails production startup or disables remote with explicit error; dev bearer documented nonproduction; protocol conformance tests pass for pinned version.
- **37-F:** SDK compiles as external package, typed DTOs/errors, no token logging/persistence; sample runs against fake endpoint; no real credential requirement.
- **37-G:** Authless control API denied, RLS integration and race tests pass, remote session cannot leak another principal's context.

Extend `internal/mcpserver`, `internal/auth`, `internal/api`, add `sdk/go/akf` tests and `examples/sdk`. Run shared gates and protocol test suite. **Done:** secure opt-in remote MCP and typed client with same knowledge/experience boundaries as stdio.

## Non-goals

Building identity provider, generic remote agent execution, public unauthenticated MCP, arbitrary tool passthrough, UI, mandatory remote transport.

# KF-09 Evaluation

## Goal

Measure whether a knowledge change improves a fixed task set, and keep golden answers out of the curator prompt. Add the optional OpenAI-compatible model adapter only after the deterministic loop exists. The adapter cannot publish a token that the cited evidence does not contain.

## Inputs / outputs

- Input: `examples/banking/tests/cases.json` (20 cases: 10 documentation gaps, 5 contradictions, 5 negative) and a search function over the published index.
- Output: pass/fail counts and critical regressions.

## Non-goals

- Training a model.
- Calling a live model API. The adapter test uses httptest. An empty API key fails closed.

## Interfaces

- `evaluations.Load`, `RunRetrieval`, `RunDecisions`, `CuratorPrompt`
- `model.OpenAI.Complete`
- `model.Propose`, which validates the model's JSON with `curator.Validate`

`CuratorPrompt` includes the retrieval query and untrusted evidence. It does not include `answer` or `sentinel`.

## Failure modes

- Fewer than 20 cases: load error.
- Model edit introduces `password` when the contract says `eventId`: validation error, no proposal.
- On the stale banking index, `mov-dedupe-key` fails. That is the baseline the demo has to beat.

## Tests

The dataset shape is checked, every sentinel stays out of the prompt, all 10 decision cases match their expected decision, and the stale index fails the critical dedupe retrieval. The adapter records token usage from a fake server.

## Definition of done

`go test ./internal/evaluations ./internal/model` passes without a network call to a model provider.

# KF-38 — End-to-end banking knowledge factory showcase

**Priority:** P2 · **Depends on:** KF-22–37 · **Release gate:** V2 integrated demonstration

## Goal / baseline

`examples/banking` and `TestBankingLearningCycle` demonstrate correction of movement-event dedupe key from `movementId` to `eventId` using recorded Avro evidence and simulated merge. Expand into a reproducible continuous learning showcase covering discovery, curator, evidence, human review, safe release, execution replay, rollback and metrics. Keep `dipjyotimetia/distributed-systems` read-only; no live banking/customer data. Prove actual fixture task improvement, not just retrieval string matches.

## Deliverables and scenario contracts

Extend `examples/banking/` with versioned synthetic fixture sources, knowledge tree revisions, experience envelopes, task cases, expected control assertions and `README.md` runbook. Use recorded fake GitHub/Notion/Slack responses, in-memory/directory publisher with explicit human-review simulation (test-only `HumanMerge`, not curator API), real PostgreSQL app-role RLS, Temporal test environment plus live Temporal CI. Provide `make demo-v2` or `kfactory demo banking --scenario all --format json|markdown` (choose one documented primary command; CLI may wrap tests/fixture runner but must return nonzero on failed scenario). No external credentials, no network except local Compose; optional live model/GitHub sandbox explicitly labelled, not required. Default deterministic mode demonstrates fixture execution; do not represent as live LLM benchmark.

## Security / failure handling

Use test-owned synthetic workspaces and credential-free fake providers. Explicit dev flag, refuse actual production endpoint/repo or privileged DB for application tests. No writes to banking source repository, no real customer payloads, no unrestricted sandbox/shell, no skill execution. Human merge simulated only via test fixture not production capability. Invalid auth, stale candidate, revoke, secret injection and failure receipts must be independently asserted. Report safe partial failure and nonzero exit; teardown only created resources, no hiding skipped tests. Preserve audit proof and verify hash chain.

## Acceptance criteria / tests
- **38-A:** One documented command reproducibly runs six scenarios on clean local stack with no paid provider/credentials; report includes exact fixture/commit/config and actual statuses.
- **38-B:** A/B each demonstrate objective fail→pass with identical runner/tools and changed knowledge; held-out split and independent check evidence; no fabricated model result.
- **38-C:** Before review candidate invisible; verified gap tied to actual merged proposal and targeted proof; unrelated proposal not verified; duplicate/missed events recover.
- **38-D:** C/D detect correct scoped issue, ignore unrelated infra failure, revoke affected data immediately; typed contracts do not execute queries.
- **38-E:** E denies malicious tool, trace path, candidate access and invalid remote auth; no secret sentinel in DB/log/Git/history.
- **38-F:** F critical regression blocks publication, rollback survives restart/push, stale promotion fenced, reviewed remediation and operator resume succeed.
- **38-G:** Repeated run deterministic (except documented timing/IDs), all workspace/RLS/race/Temporal integration tests pass; safe cleanup; metrics exact fixture denominators and invalids.
- **38-H:** README/runbook/architecture/security/evaluation docs match implementation; CI report archived, no claims of live model performance unless separately executed.

Extend `internal/demo/banking_test.go`, `temporal_live_test.go`, add scenario harness and `examples/banking/tests/` fixtures. Run shared gates and `make demo-v2` (or documented chosen command), capture real output. **Done:** reproducible full-loop demonstration and measured fixture learning, safety guarantees tested, V2 release evidence available for review.

## Non-goals

Changing external banking application, real production data or live payment flows, automatic PR merge, mandatory live LLM evaluation, dashboard frontend, pretending fixture benchmark proves general agent performance.

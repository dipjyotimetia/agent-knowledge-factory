# KF-15 Safe publication

## Goal

A create-skill proposal, a failed webhook, and a regressed tree must not publish the wrong revision.

## Inputs / outputs

- `Steps.Prepare` persists `update` and `create-skill`. Any other decision moves the gap to `insufficient-evidence` and does not open a pull request.
- `POST /v1/github/webhook` records the delivery id only after the signal or the reconcile succeeds. A 502 leaves the id free so GitHub can retry.
- `Index.Stage` writes a candidate SHA. `Index.Promote` moves `published_sha` only after `commitCandidate` accepts the score. A critical regression calls `DropStage` and leaves the previous SHA in place.

## Non-goals

- Reverting the Git default branch. Rollback of the index is still `kfactory rollback`.

## Definition of done

`go test ./internal/workflows ./internal/api` passes. A create-skill gap reaches `proposal-ready`. A forged merge SHA does not promote. A failed signal is not stored as a duplicate.
